**I. Core Architecture & Workflow**

The core idea is to transform the Markdown input into a structured data representation and then render that data using a custom UI system. This system will handle the layout and styling of the various components (sections, cards, formulas, tables, etc.).

1. **Markdown Parsing:**  Use a Markdown parser (like `markdown` in Python or similar libraries in other languages) to initially parse the input.  *Crucially, this parser doesn't directly render.* Instead, it extracts the content and identifies structural elements (headings, paragraphs, lists, tables, LaTeX formulas).
2. **Section Detection & Card Creation:**  Analyze the headings (e.g., `#`, `##`, `###`) to automatically detect section boundaries.  For each detected section, create a `SectionCard` object.  The heading text becomes the card's title.
3. **Formula Extraction & FormulaCard Creation:**  Identify all LaTeX formula blocks (`$$ ... $$`).  For each formula, create a `FormulaCard` object.  The formula itself is rendered within the card. This is where the `formula`, `title`, `surroundingContext`, and `variables` data are stored.
4. **Table Rendering:** Identify Markdown tables. Convert them into `TableCard` objects.
5. **Content Assembly:**  Assemble the `SectionCard` and `FormulaCard` objects into a logical order.  This order is determined by the Markdown document's structure.  Consider using a tree-like structure to represent the document hierarchy.
6. **UI Rendering:**  Use a UI framework (e.g., React, Vue.js, or a custom HTML/CSS solution) to render the assembled data into a visually appealing and interactive textbook format.  This is where the styling and layout are applied.

**IV.  Formula Extraction Process (Detailed)**

This is a critical component.  Here's how it will work:

1.  **Iterate through the parsed Markdown content.**
2.  **For each block of text, check if it contains LaTeX formula delimiters (`$$` and `$$`).**
3.  **If a delimiter is found:**
    *   **Extract the content *between* the delimiters.** This is the LaTeX formula.
    *   **Extract surrounding context.**  This is the text immediately *before* and *after* the formula.  This provides context for understanding the formula's meaning.
    *   **Use a LaTeX parser (e.g., `sympy` in Python) to identify variables.**  This is more advanced and requires parsing the LaTeX expression.  `sympy` can extract variables, constants, and functions.
    *   **Create a `FormulaCard` object with the extracted data.**
    *   **Store the `FormulaCard` object in a list.**
4.  **After processing all Markdown content, the list of `FormulaCard` objects is available for use in the UI rendering process.**  This list is *not* parsed again later.

```markdown

This law is fundamental to classical mechanics.
```

Here's how it would be processed:

1.  **Parsing:**  The Markdown parser identifies the heading "Newton's Second Law" and the LaTeX formula `F = ma`.

3.  **FormulaCard:** A `FormulaCard` is created with:
    *   `title`: "Newton's Second Law"
    *   `formula`: `F = ma` (rendered by MathJax/KaTeX)
    *   `explanation`: (Empty, or could be populated with a default explanation)
    *   `variables`: `['F', 'm', 'a']`
    *   `lab_url`:  (Pointing to the Formula Lab for `F = ma`)
4.  **Assembly:**  The `SectionCard` and `FormulaCard` are combined into a `Document` object, with the `FormulaCard` appearing after the paragraph.
